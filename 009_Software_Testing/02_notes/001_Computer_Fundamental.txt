0.1 WHAT IS A COMPUTER?
======================================================================

DEFINITION
----------
A computer is an electronic device that accepts data as input,
processes it according to instructions, stores data, and produces
results as output.

BASIC WORKING MODEL
-------------------

    +-------------+
    |    INPUT    |
    +-------------+
           |
           v
    +-------------+
    | PROCESSING  |
    +-------------+
           |
           v
    +-------------+
    |   OUTPUT    |
    +-------------+
           |
           v
    +-------------+
    |   STORAGE   |
    +-------------+

Example: Calculating 10 + 20

    Input:
        10 + 20

    Processing:
        CPU executes the required instructions.

    Output:
        30

    Storage:
        The result can be saved in a file or database.

IMPORTANT COMPONENTS
--------------------
1. Input devices:
   Keyboard, mouse, scanner, microphone.

2. Processing unit:
   CPU executes instructions.

3. Output devices:
   Monitor, printer, speakers.

4. Memory:
   Stores data and instructions temporarily or permanently,
   depending on the memory type.

5. Software:
   Provides instructions that tell the computer what to do.

QA ENGINEER CONNECTION
----------------------
A QA engineer tests software running on computers, servers,
mobile devices, and other systems.

Understanding computer fundamentals helps a tester investigate:
- Application crashes.
- Slow application performance.
- Insufficient memory.
- Storage-related problems.
- Operating-system compatibility issues.


======================================================================
0.2 HARDWARE VS SOFTWARE
======================================================================

A. HARDWARE
-----------

Hardware refers to the physical components of a computer that
can be physically touched.

Examples:
- CPU
- RAM
- SSD/HDD
- Keyboard
- Mouse
- Monitor
- Network card

B. SOFTWARE
-----------

Software is a collection of programs and instructions that tell
computer hardware what tasks to perform.

Examples:
- Windows
- Linux
- Google Chrome
- Microsoft Word
- Postman
- Selenium-based test scripts

C. DIFFERENCES
--------------

Feature             Hardware              Software
-------------------------------------------------------------
Meaning             Physical components   Programs/instructions
Physical form       Tangible              Intangible
Examples            CPU, RAM, SSD         OS, browser, test script
Failure             Physical/electronic   Logic/configuration/runtime
Replacement         Replace component     Reinstall/update/fix code
Dependency          Runs under software   Requires hardware to execute

D. HOW THEY WORK TOGETHER
-------------------------

Example: Opening a web browser

1. You click the browser icon.
2. The operating system receives the action.
3. The operating system loads the required program into memory.
4. The CPU executes its instructions.
5. The display hardware shows the browser window.

The browser is software.
The CPU, RAM, and monitor are hardware.

QA EXAMPLE
----------
Suppose a browser crashes while opening a website.

Possible causes include:
- A browser software defect.
- A compatibility issue.
- Insufficient available memory.
- A graphics driver problem.
- A problem with the website.

A tester investigates the evidence rather than assuming that
every crash is caused by the application itself.


======================================================================
0.3 CPU, RAM, STORAGE
======================================================================

These three components have different responsibilities.

----------------------------------------------------------------------
A. CPU — CENTRAL PROCESSING UNIT
----------------------------------------------------------------------

The CPU executes program instructions and performs calculations
and logical operations.

Common conceptual components:
- Arithmetic Logic Unit (ALU): performs arithmetic and logical operations.
- Control Unit (CU): coordinates instruction execution.
- Registers: hold small amounts of data used immediately by the CPU.

Example:
When a program calculates 100 + 200, the CPU performs the required
operations as part of executing the program.

Important:
A CPU does not normally keep all application data permanently.
Programs and data use different memory and storage resources.

----------------------------------------------------------------------
B. RAM — RANDOM ACCESS MEMORY
----------------------------------------------------------------------

RAM is working memory used to hold programs and data that are
currently needed.

Characteristics:
- Fast access compared with ordinary persistent storage.
- Volatile: its contents generally do not survive loss of power.
- Used by running applications and the operating system.
- Limited capacity.

Example:
When you open a browser, the operating system loads program code
and working data into memory.

If many applications run simultaneously, memory pressure may
increase and performance may deteriorate.

----------------------------------------------------------------------
C. STORAGE
----------------------------------------------------------------------

Storage keeps files and data persistently, even when the computer
is switched off.

Examples:
- SSD (Solid-State Drive)
- HDD (Hard Disk Drive)
- USB drive
- Memory card

Storage may contain:
- Operating-system files.
- Installed applications.
- Documents.
- Images and videos.
- Test scripts and reports.
- Databases and application logs.

SSD VS HDD
----------

SSD:
- Uses flash memory.
- Has no moving mechanical disk parts.
- Generally provides faster access than an HDD.

HDD:
- Uses rotating magnetic disks.
- Has moving mechanical parts.
- Often offers relatively low cost per unit of capacity.

----------------------------------------------------------------------
D. CPU VS RAM VS STORAGE
----------------------------------------------------------------------

CPU:
    Executes instructions.

RAM:
    Holds active programs and working data.

Storage:
    Keeps programs and files persistently.

Example: Opening a text editor

1. The application is stored on an SSD or HDD.
2. The operating system loads the required program into RAM.
3. The CPU executes its instructions.
4. The application displays its interface.
5. When you save a document, the data is written to storage.

----------------------------------------------------------------------
E. MEMORY AND STORAGE UNITS
----------------------------------------------------------------------

Bit:
    A binary digit: 0 or 1.

Byte:
    8 bits.

Common units:
    KB — Kilobyte
    MB — Megabyte
    GB — Gigabyte
    TB — Terabyte

In common binary-based computer memory calculations:
    1 KiB = 1024 bytes
    1 MiB = 1024 KiB
    1 GiB = 1024 MiB
    1 TiB = 1024 GiB

Storage manufacturers may use decimal units:
    1 kB = 1000 bytes
    1 MB = 1000 kB
    1 GB = 1000 MB
    1 TB = 1000 GB

Therefore, displayed capacities can differ depending on the
unit convention used.

----------------------------------------------------------------------
F. QA ENGINEER CONNECTION
----------------------------------------------------------------------

Scenario 1: Application is slow.
Possible investigation areas:
- CPU utilization.
- Available RAM.
- Disk activity.
- Network conditions.
- Application logs.

Scenario 2: Test execution fails because a file cannot be saved.
Possible investigation areas:
- Available disk space.
- File permissions.
- Invalid file path.
- Whether the storage device is accessible.

Scenario 3: An application behaves differently on two computers.
Possible investigation areas:
- Operating-system versions.
- Hardware resources.
- Installed software versions.
- Environment configuration.


======================================================================
0.4 OPERATING SYSTEM
======================================================================

DEFINITION
----------
An operating system (OS) is system software that manages computer
hardware and provides services for applications.

EXAMPLES
--------
Desktop/laptop:
- Microsoft Windows
- Linux distributions
- macOS

Mobile:
- Android
- iOS

CORE RESPONSIBILITIES
---------------------
1. Process management:
   Manages running programs and their execution.

2. Memory management:
   Allocates and manages memory used by programs.

3. File management:
   Organizes files and directories and controls access to them.

4. Device management:
   Coordinates the use of devices through suitable system software
   and drivers.

5. Security and access control:
   Supports user accounts, permissions, and other security controls.

6. User interface:
   Provides graphical interfaces and/or command-line interfaces.

----------------------------------------------------------------------
A. GUI — GRAPHICAL USER INTERFACE
----------------------------------------------------------------------

A GUI allows users to interact with a computer through visual
elements such as:
- Windows.
- Icons.
- Menus.
- Buttons.
- File managers.

Example:
Opening a folder by double-clicking it in Windows File Explorer.

Advantages:
- Easy for beginners.
- Visual navigation.
- Convenient for many everyday tasks.

----------------------------------------------------------------------
B. CLI — COMMAND-LINE INTERFACE
----------------------------------------------------------------------

A CLI lets users interact with the computer by entering text commands.

Examples:
- Command Prompt.
- PowerShell.
- Linux terminal.
- macOS terminal.

Example:
    pwd

On Linux/macOS, this displays the current working directory.

CLI tools are useful for:
- Running test scripts.
- Inspecting files.
- Viewing logs.
- Managing source code.
- Automating repetitive tasks.

----------------------------------------------------------------------
C. WHY QA ENGINEERS NEED OS KNOWLEDGE
----------------------------------------------------------------------

A tester may need to:
- Install testing tools.
- Start or stop applications.
- Inspect logs.
- Check environment variables.
- Verify file permissions.
- Run automation scripts.
- Investigate operating-system-specific failures.

Example:
A test script works on Linux but fails on Windows.

Potential causes:
- Different file-path conventions.
- Different environment variables.
- Missing dependencies.
- Case-sensitive versus case-insensitive file systems.
- Different shell commands.


======================================================================
0.5 FILES AND DIRECTORIES
======================================================================

A. FILE
-------

A file is a named collection of data stored on a computer.

Examples:
    report.txt
    test_cases.xlsx
    screenshot.png
    test_script.py
    application.log

Files may contain text, images, program code, configuration,
test results, or other data.

B. DIRECTORY / FOLDER
---------------------

A directory is a structure used to organize files and other
directories.

Example:

    QA_Project/
    |
    +-- test_cases/
    |   +-- login_tests.xlsx
    |   +-- checkout_tests.xlsx
    |
    +-- scripts/
    |   +-- test_login.py
    |
    +-- reports/
    |   +-- execution_report.html
    |
    +-- logs/
        +-- application.log

C. FILE EXTENSIONS
------------------

.txt    Text file
.pdf    Portable Document Format
.docx   Word document
.xlsx   Excel workbook
.png    Image
.jpg    Image
.py     Python source file
.java   Java source file
.js     JavaScript source file
.json   JSON data file
.html   HTML document
.log    Log file

Important:
A file extension is a naming convention. Changing the extension
alone does not necessarily convert a file's actual format.

D. ABSOLUTE VS RELATIVE PATH
----------------------------

An absolute path specifies a location from a filesystem root
or drive root.

Example on Windows:
    C:\Users\Tester\Documents\report.txt

Example on Linux:
    /home/tester/Documents/report.txt

A relative path specifies a location relative to the current
working directory or another defined base directory.

Example:
    reports/report.txt

The relative path works only when interpreted from an appropriate
base directory.

E. COMMON FILE OPERATIONS
-------------------------
- Create.
- Read.
- Write.
- Rename.
- Copy.
- Move.
- Delete.

F. FILE PERMISSIONS
-------------------

Operating systems can control which users or processes may:
- Read a file.
- Write to a file.
- Execute a file.

A permission issue may cause an automated test to fail even when
the test code itself is correct.

G. QA ENGINEER EXAMPLE
----------------------

Suppose a test script attempts to read:

    test_data/users.csv

But the test fails with "file not found".

Possible reasons:
1. The file does not exist.
2. The filename is incorrect.
3. The script uses the wrong working directory.
4. The relative path is incorrect.
5. The file is unavailable in the execution environment.

A tester should verify the actual path and environment before
changing the test logic.


======================================================================
0.6 PROCESSES AND APPLICATIONS
======================================================================

A. APPLICATION
--------------

An application is software designed to perform tasks for a user
or another system.

Examples:
- Web browser.
- Text editor.
- Calculator.
- Postman.
- Test management application.

B. PROCESS
----------

A process is an instance of a program that is executing.

A program stored on disk is not the same thing as a running process.

Example:
A browser application may be installed on disk. When you launch it,
the operating system creates one or more processes to execute it.

A single application can use multiple processes.

C. PROCESS VS PROGRAM
---------------------

Program:
    Stored instructions or executable code.

Process:
    A running instance of a program, with execution state and
    resources managed by the operating system.

D. THREAD — BASIC IDEA
----------------------

A thread is a unit of execution within a process.

A process may contain multiple threads that perform different
tasks. Threads within a process generally share that process's
memory space.

For this chapter, remember:
    Program = instructions stored for execution.
    Process = executing instance.
    Thread = execution unit within a process.

E. PROCESS STATES — SIMPLIFIED MODEL
------------------------------------

Common conceptual states include:

    NEW
     |
     v
    READY <----------+
     |               |
     v               |
   RUNNING           |
     |               |
     +----> WAITING -+
     |
     v
  TERMINATED

READY:
    Waiting for CPU execution.

RUNNING:
    Currently executing on a CPU.

WAITING/BLOCKED:
    Waiting for an event, such as I/O completion.

TERMINATED:
    Execution has finished or the process has been ended.

Operating systems may use more detailed state models.

F. TASK MANAGER / SYSTEM MONITOR
-------------------------------

Windows Task Manager and Linux/macOS system-monitoring tools
help users inspect running processes and resource usage.

They can help investigate:
- High CPU utilization.
- High memory usage.
- Unresponsive applications.
- Unexpected background processes.

G. QA ENGINEER SCENARIO
-----------------------

An automated test launches a browser and then hangs.

Investigation steps:
1. Check whether the browser process started.
2. Check whether the browser is responsive.
3. Inspect the automation output and logs.
4. Check CPU and memory utilization.
5. Check whether the test is waiting for an unavailable element.
6. Determine whether the problem is environmental, application-related,
   or caused by the automation script.

Do not assume that every timeout means the application is defective.

0.7 COMMAND LINE BASICS
======================================================================

The command line is a text-based interface used to execute commands.

The exact commands differ between shells and operating systems.

This section introduces basic navigation and file operations.

----------------------------------------------------------------------
A. WINDOWS COMMAND PROMPT (CMD)
----------------------------------------------------------------------

1. Display the current directory:

    cd

2. List files and directories:

    dir

3. Change directory:

    cd folder_name

4. Move to the parent directory:

    cd ..

5. Create a directory:

    mkdir QA_Project

6. Create a simple text file:

    echo Hello QA > notes.txt

7. Display a text file:

    type notes.txt

8. Delete a file:

    del notes.txt

WARNING:
    del can permanently remove a file from the normal filesystem
    view. Verify the target before executing deletion commands.

----------------------------------------------------------------------
B. LINUX / macOS TERMINAL
----------------------------------------------------------------------

1. Display the current directory:

    pwd

2. List files and directories:

    ls

3. Change directory:

    cd folder_name

4. Move to the parent directory:

    cd ..

5. Create a directory:

    mkdir QA_Project

6. Create a simple text file:

    echo "Hello QA" > notes.txt

7. Display a text file:

    cat notes.txt

8. Delete a file:

    rm notes.txt

WARNING:
    rm normally deletes the specified file without moving it to
    a graphical trash/recycle bin. Verify the target first.

----------------------------------------------------------------------
C. COMMAND COMPARISON
----------------------------------------------------------------------

Task                Windows CMD         Linux/macOS
-----------------------------------------------------
Current directory   cd                  pwd
List contents       dir                 ls
Change directory    cd folder_name      cd folder_name
Parent directory    cd ..               cd ..
Create directory    mkdir name          mkdir name
Display text file   type file.txt       cat file.txt
Delete file         del file.txt        rm file.txt

Note:
PowerShell is a different shell from Windows CMD. Some commands
and aliases differ, so do not assume every CMD command behaves
identically in PowerShell.

----------------------------------------------------------------------
D. PRACTICAL EXERCISE — CREATE A QA PROJECT
----------------------------------------------------------------------

WINDOWS CMD:

    mkdir QA_Project
    cd QA_Project
    mkdir test_cases
    mkdir scripts
    mkdir reports
    mkdir logs
    dir

LINUX / macOS:

    mkdir QA_Project
    cd QA_Project
    mkdir test_cases scripts reports logs
    ls

Expected directory structure:

    QA_Project/
    |
    +-- test_cases/
    +-- scripts/
    +-- reports/
    +-- logs/

This structure separates test cases, automation code, reports,
and logs.

----------------------------------------------------------------------
E. COMMAND-LINE TERMS
----------------------------------------------------------------------

Terminal:
    An application that provides access to a command-line session.

Shell:
    A program that interprets commands, such as Bash, Zsh, CMD,
    or PowerShell.

Command:
    An instruction entered into the shell.

Argument:
    A value supplied to a command.

Working directory:
    The directory used as the current location for relative paths.

Environment variable:
    A named value available to processes, often used for configuration.

Example:

    cd reports

Here:
    cd       = command
    reports  = argument

----------------------------------------------------------------------
F. COMMAND-LINE TROUBLESHOOTING
----------------------------------------------------------------------

Problem: "Command not found" or "not recognized".

Possible reasons:
- The command is unavailable in that shell.
- The tool is not installed.
- The executable is not on PATH.
- The command name is incorrect.

Problem: "File not found".

Possible reasons:
- Incorrect filename.
- Wrong working directory.
- Incorrect relative path.
- File does not exist.

Problem: "Permission denied".

Possible reasons:
- Insufficient permissions.
- File ownership or permission configuration.
- Restricted execution environment.

QA TIP:
Read the complete error message. Check the command, current
directory, path, permissions, and tool installation before
assuming the software has a defect.


======================================================================
PRACTICAL QA SCENARIO
======================================================================

SCENARIO:
An automation script fails when it tries to read test data.

Error:
    FileNotFoundError: users.csv

INVESTIGATION:

Step 1:
    Check whether users.csv exists.

Step 2:
    Confirm the directory containing users.csv.

Step 3:
    Check the script's current working directory.

Step 4:
    Verify whether the script uses an absolute or relative path.

Step 5:
    Confirm the file is available in the environment where the
    test is running.

Step 6:
    Run the test again after correcting the confirmed cause.

LESSON:
A test failure does not automatically prove that the application
is defective. The cause may be test data, configuration,
environment, permissions, or application behavior.
